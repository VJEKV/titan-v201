ОБЩАЯ ЛОГИКА ФОРМИРОВАНИЯ ВЫБОРКИ ЗАКАЗОВ
================================================================================

ВХОДНЫЕ ПАРАМЕТРЫ:
- BUKRS - Балансовая единица
- INGRP - Группа плановиков  
- BEGIN - Начало периода анализа
- END - Окончание периода анализа

АЛГОРИТМ ПЕРВИЧНОЙ ВЫБОРКИ:
1. По BUKRS определить T001K-BWKEY, затем T001W-WERKS (заводы)
2. Выбрать заказы AUFNR из AFKO, AUFK, AFIH где:
   - AFKO-GSTRP >= BEGIN
   - AFKO-GLTRP <= END
   - AUFK-AUART = допустимые виды заказов (из ZTBIS_MAP21)
   - AFIH-IWERK = WERKS
   - AFIH-INGRP = INGRP

ИСКЛЮЧЕНИЯ ИЗ ВЫБОРКИ:
- Метка удаления: JEST-OBJNR=OR<номер заказа>, STAT=I0076, INACT=<пусто>
- Статус НЕВЫ: JEST-OBJNR=OR<номер заказа>, STAT=I0015, INACT=<пусто>

СИСТЕМНЫЕ СТАТУСЫ ЗАКАЗОВ:
- I0001 = ОТКР (Открыто)
- I0002 = ДЕБЛ (Деблокировано)
- I0015 = НЕВЫ (Не выполнено)
- I0045 = ТЗКР (Технически закрыто)
- I0046 = ЗАКР (Закрыто)
- I0076 = МТКУ (Метка удаления)

--------------------------------------------------------------------------------
МЕТОД С1М1: Оценка отклонений затрат План/Факт
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление системности закрытия заказов по завышенной стоимости

ПЕРВИЧНАЯ ВЫБОРКА:
- Только закрытые заказы: STAT = ЗАКР, ТЗКР
- Исключить заказы без отклонения: FLAG = <пусто> (где PLAN = FACT)

РАСЧЕТ ОТКЛОНЕНИЯ:
D1010 = (FACT/PLAN - 1) * 100%

Особые случаи:
- Если PLAN=0, FACT≠0: D1010 = 100%
- Если PLAN≠0, FACT=0: D1010 = -100%

ФИЛЬТРАЦИЯ:
- Для FLAG=P (план > факт): оставить если |D1010| > N1010_P
- Для FLAG=F (факт > план): оставить если |D1010| > N1010_F

--- ПОДМЕТОД 1.01.1 (доля ТМ в группе плановиков) ---

Группировка по группам плановиков (INGRP), затем по установкам (TPLMA)

Расчет по группе плановиков:
DGRPL_P = Σ(PLAN - FACT) для FLAG=P
DGRPL_F = Σ(FACT - PLAN) для FLAG=F

Расчет по ТМ установки:
DGRPLTM_P = Σ(PLAN - FACT) для FLAG=P
DGRPLTM_F = Σ(FACT - PLAN) для FLAG=F

Расчет доли:
D1011_P = (DGRPLTM_P / DGRPL_P) * 100%
D1011_F = (DGRPLTM_F / DGRPL_F) * 100%

ALERT: если D1011_P > N1011_P или D1011_F > N1011_F

--- ПОДМЕТОД 1.01.2 (доля среднего по ТМ от среднего по ГрупПлан) ---

Среднее отклонение на заказ по группе плановиков:
DSRGRPL_P = DGRPL_P / N_заказов_в_группе
DSRGRPL_F = DGRPL_F / N_заказов_в_группе

Среднее отклонение на заказ по ТМ:
DSRGRPLTM_P = DGRPLTM_P / N_заказов_по_ТМ
DSRGRPLTM_F = DGRPLTM_F / N_заказов_по_ТМ

Расчет:
D1012_P = (DSRGRPLTM_P / DSRGRPL_P) * 100%
D1012_F = (DSRGRPLTM_F / DSRGRPL_F) * 100%

ALERT: если D1012_P > N1012_P или D1012_F > N1012_F

--- ПОДМЕТОД 1.01.3 (доля Подрядчика) ---

Исключить заказы: PODR = MULTI или PODR = <пусто>

По каждому подрядчику в рамках завода:
DPOD_P = Σ(PLAN - FACT) для FLAG=P
DPOD_F = Σ(FACT - PLAN) для FLAG=F

По заводу:
DWERK_P = Σ(PLAN - FACT) всех заказов
DWERK_F = Σ(FACT - PLAN) всех заказов

Доля подрядчика:
D1013_P = (DPOD_P / DWERK_P) * 100%
D1013_F = (DPOD_F / DWERK_F) * 100%

ALERT: если |D1013_P| > N1013_P или |D1013_F| > N1013_F

--- ПОДМЕТОД 1.01.4 (доля по степени критичности) ---

Исключить заказы: ABCKZ = <пусто>

По группе критичности:
DKRIT_P = Σ(PLAN - FACT) для FLAG=P
DKRIT_F = Σ(FACT - PLAN) для FLAG=F

Доля группы критичности:
D1014_P = (DKRIT_P / ΣDKRIT_P) * 100%
D1014_F = (DKRIT_F / ΣDKRIT_F) * 100%

ALERT: если D1014_P > N1014_P или D1014_F > N1014_F

--- ПОДМЕТОД 1.01.5 (доля по классу) ---

Исключить заказы: CLASS = <пусто>

По классу ЕО:
DCLAS_P = Σ(PLAN - FACT) для FLAG=P
DCLAS_F = Σ(FACT - PLAN) для FLAG=F

Доля класса:
D1015_P = (DCLAS_P / ΣDCLAS) * 100%
D1015_F = (DCLAS_F / ΣDCLAS) * 100%

ALERT: если D1015_P > N1015_P или D1015_F > N1015_F

ПЕРЕМЕННЫЕ:
- N1010_P, N1010_F - порог первичного отклонения (%)
- N1011_P, N1011_F - порог доли ТМ в ГрПлан (%)
- N1012_P, N1012_F - порог среднего отклонения (%)
- N1013_P, N1013_F - порог доли подрядчика (%)
- N1014_P, N1014_F - порог доли критичности (%)
- N1015_P, N1015_F - порог доли класса (%)

МЕТОД С1М2: Оценка отклонений в рамках вида объекта
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление завышения затрат на однотипное оборудование

ПЕРВИЧНАЯ ВЫБОРКА:
- Только закрытые заказы: STAT = ЗАКР, ТЗКР
- Группировка по виду объекта ЕО (EQART)

--- ПОДМЕТОД 1.02.1 (отклонение по ЕО) ---

Средние затраты на одну ЕО в группе вида объекта:
FSRVOEO = ΣFACT / N_ЕО

Отклонение для каждой ЕО:
D1021 = (ΣFACT_ЕО / FSRVOEO - 1) * 100%

ALERT: если D1021 > N1021

--- ПОДМЕТОД 1.02.2 (отклонение заказа в группе вида) ---

Средние затраты на один заказ в группе вида объекта:
FSRVOZ = ΣFACT / N_заказов

Отклонение для каждого заказа:
D1022 = (FACT / FSRVOZ - 1) * 100%

ALERT: если D1022 > N1022

ПЕРЕМЕННЫЕ:
- N1021 - порог отклонения по ЕО (%)
- N1022 - порог отклонения заказа (%)

МЕТОД С1М4: Оценка отклонения плановых трудозатрат от фактических
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление дефектов планирования трудозатрат

ПЕРВИЧНАЯ ВЫБОРКА:
- Только закрытые заказы: STAT = ЗАКР, ТЗКР
- Исключить: PLANT = 0 и FACTT = 0

РАСЧЕТ:
D1040 = (FACTT / PLANT - 1) * 100%

ALERT:
- Если D1040 > N1040_F (факт > план)
- Если D1040 < 0 и |D1040| > N1040_P (план > факт)

ПЕРЕМЕННЫЕ:
- N1040_P - порог при план > факт (%)
- N1040_F - порог при факт > план (%)

--------------------------------------------------------------------------------
МЕТОД С1М5: Оценка отклонений плановых трудозатрат от нормативных
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление отклонений от техкарты

ПЕРВИЧНАЯ ВЫБОРКА:
- Все заказы из общей выборки
- Исключить заказы без техкарты (PLNTY, PLNNR, PLNKN, ZAEHL не найдены)

ОПРЕДЕЛЕНИЕ НОРМАТИВНОГО ВРЕМЕНИ:
1. По AUFNR -> AFKO-AUFPL
2. По AUFPL -> AFVC (PLNTY, PLNNR, ZAEHL, PLNKN)
3. По этим полям -> PLPO-ARBEI (нормативное время)
4. NORMT = Σ(PLPO-ARBEI) с пересчетом в Ч.Ч.

РАСЧЕТ:
D1050 = (PLANT / NORMT - 1) * 100%

ALERT: если D1050 > N1050

ПЕРЕМЕННЫЕ:
- N1050 - порог отклонения от нормы (%)

МЕТОД С1М6: Оценка отклонения затрат для ремонта одного и того же объекта

ЦЕЛЬ: Выявление завышения затрат относительно исторических данных

ПЕРВИЧНАЯ ВЫБОРКА:

- Исключить: EQUNR = <пусто>
- Расширить период на N1060 лет назад
- Группировать по ЕО, виду заказа (AUART), виду работ (ILART)
- Исключить группы с одним заказом

РАСЧЕТ МЕДИАНЫ (без контролируемого заказа):
FACTm - медиана фактических затрат
FACTTm - медиана фактических трудозатрат

--- ПОДМЕТОД 1.06.1 (отклонение затрат) ---

D1061 = (FACT / FACTm - 1) * 100%

ALERT: если D1061 > N1061

--- ПОДМЕТОД 1.06.2 (отклонение трудозатрат) ---

D1062 = (FACTT / FACTTm - 1) * 100%

ALERT: если D1062 > N1062

ПЕРЕМЕННЫЕ:
- N1060 - количество лет для анализа
- N1061 - порог отклонения затрат (%)
- N1062 - порог отклонения трудозатрат (%)

МЕТОД С1М12: Оценка отклонения сроков выполнения от фактического простоя
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление превышения времени работ над временем простоя

ПЕРВИЧНАЯ ВЫБОРКА:
- Только закрытые заказы: STAT = ЗАКР, ТЗКР
- Исключить: FACTT не определена
- Исключить: QMNUM = <пусто>
- Исключить: время простоя TPRS = 0 или N_исполнителей NISP = 0

ОПРЕДЕЛЕНИЕ КОЛИЧЕСТВА ИСПОЛНИТЕЛЕЙ:
1. По AUFNR -> AFKO-AUFPL
2. Исключить операции с меткой удаления (STAT=I0013)
3. NISP = MAX(AFVC-ANZZL) из оставшихся операций

ВРЕМЯ ПРОСТОЯ:
TPRS = QMIH-AUSZT (в часах, исходно в секундах)

РАСЧЕТ:
D1120 = FACTT - (TPRS * NISP)

ALERT: если D1120 > 0 (работали дольше, чем простаивало)

--------------------------------------------------------------------------------
МЕТОД С1М13: Оценка изменений ключевых параметров заказа
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление аномальных изменений в заказах

ПЕРВИЧНАЯ ВЫБОРКА:
- Только деблокированные и закрытые: STAT = ДЕБЛ, ЗАКР, ТЗКР

--- ПОДМЕТОД 1.13.1 (изменение системного статуса) ---

Условие 1 - ДЕБЛ после снятия ТЗКР:
- Текущий статус ДЕБЛ (I0002, INACT=<пусто>, CHGNR=MAX)
- И был удален статус ТЗКР (I0045, INACT=X)
ALERT: если условие выполнено

Условие 2 - ТЗКР установлен 2+ раз:
- Текущий статус ЗАКР или ТЗКР (I0045 или I0046, INACT=<пусто>, CHGNR=MAX)
- И статус ТЗКР (I0045) встречается с CHGNR >= 3
ALERT: если условие выполнено

--- ПОДМЕТОД 1.13.2 (изменение ключевых полей) ---

Проверка через CDPOS (OBJECTID = 40030<номер заказа>):

1) Изменение ТМ:
   - FNAME = 'TPLNR'
   - VALUE_OLD(*) <> VALUE_NEW и VALUE_NEW(*) <> VALUE_OLD
   - НЕ считается изменением: укрупнение/детализация адреса ТМ
   ALERT: если изменение ТМ

2) Изменение ЕО:
   - FNAME = 'EQUNR'
   ALERT: если была запись

3) Изменение базисного срока начала (>2 изменений):
   - FNAME = 'GSTRP'
   - COUNT записей где CDHDR-VERSION <> <пусто> > 2
   ALERT: если условие выполнено

4) Изменение базисного срока окончания (>2 изменений):
   - FNAME = 'GLTRP'
   - COUNT записей где CDHDR-VERSION <> <пусто> > 2
   ALERT: если условие выполнено

МЕТОД С2М1: Выявление необработанных сообщений ТОРО
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление сообщений о неисправности без привязанных заказов

ПЕРВИЧНАЯ ВЫБОРКА:
1. Выбрать сообщения QMNUM из QMEL:
   - QMEL-STRMN <= END
   - QMEL-LTRMN >= BEGIN
   - QMEL-QMART = виды из ZTBIS_MAP22 для METHOD=2010
2. Ограничить по БЕ: QMIH-ILOAN -> ILOA-BUKRS
3. Исключить: метка удаления (JEST-OBJNR=QM<номер>, STAT=I0076)

ALERT: если QMEL-AUFNR = <пусто>

Дополнительные поля для отчета:
- QMEL-ERNAM (автор)
- QMEL-ERDAT (дата создания)

--------------------------------------------------------------------------------
МЕТОД С2М2: Выявление часто выходящего из строя оборудования
--------------------------------------------------------------------------------

ЦЕЛЬ: Выявление оборудования с высокой частотой отказов

ПЕРВИЧНАЯ ВЫБОРКА:
1. Выбрать сообщения QMNUM из QMEL:
   - QMEL-STRMN <= END
   - QMEL-LTRMN >= BEGIN
   - QMEL-QMART = виды из ZTBIS_MAP22 для METHOD=202*
2. Определить для каждого сообщения:
   - EQUNR = QMIH-EQUNR
   - TPLNR = ILOA-TPLNR (по ILOAN)
   - TPLMA = установка (по маске XXNN.XXX)

--- ПОДМЕТОД 2.02.1 (по установке) ---

D2021 = (N_сообщений_по_установке / N_всего) * 100%

ALERT: если D2021 >= N2021 -> все сообщения установки в alert

--- ПОДМЕТОД 2.02.2 (по ТМ) ---

D2022 = (N_сообщений_по_ТМ / N_сообщений_по_установке) * 100%

ALERT: если D2022 >= N2022 -> все сообщения ТМ в alert

--- ПОДМЕТОД 2.02.3 (по ЕО) ---

D2023 = (N_сообщений_по_ЕО / N_сообщений_по_ТМ) * 100%

ALERT: если D2023 >= N2023 -> все сообщения ЕО в alert

ПЕРЕМЕННЫЕ:
- N2020 - критичное количество сообщений для ЕО
- N2021 - порог доли по установке (%)
- N2022 - порог доли по ТМ (%)
- N2023 - порог доли по ЕО (%)

СТРАТЕГИЯ С4: АНАЛИЗ КОНСИСТЕНТНОСТИ ДАННЫХ (отчет)
================================================================================

ЦЕЛЬ: Оценка полноты данных в заказах

ПЕРВИЧНАЯ ВЫБОРКА:
- Только: STAT = ЗАКР, ТЗКР, ДЕБЛ

КРИТЕРИИ ПРОВЕРКИ (каждый = 1 флаг ошибки):
1. GSTRI = <пусто> - нет факт. начала
2. GETRI = <пусто> - нет факт. окончания
3. PLAN = <пусто> при FACT <> <пусто> - нет плана при наличии факта
4. FACT = <пусто> при PLAN <> <пусто> - нет факта при наличии плана
5. PLANT = <пусто> - нет план. трудозатрат
6. FACTT = <пусто> - нет факт. трудозатрат
7. USTAT < 08 - низкий пользовательский статус
8. PODR = MULTI - несколько подрядчиков
9. ABCKZ = <пусто> - нет критичности
10. CLASS = <пусто> - нет класса ЕО
11. AUART не в списке (LK01, LK02, LK03, LK04, ST01, MN01, DM01, KR01, PM01, MXUP)
12. DOCN = <пусто> - нет номера договора

ИТОГО: Подсчет количества пустых критериев по каждому заказу

================================================================================
СТРАТЕГИЯ С5: АНАЛИЗ СОБЛЮДЕНИЯ ЛИМИТА ЗАТРАТ (отчет)
================================================================================

ЦЕЛЬ: Оценка отклонений план/факт по категориям затрат

ПЕРВИЧНАЯ ВЫБОРКА:
- Только: STAT = ЗАКР, ТЗКР, ДЕБЛ

КАТЕГОРИИ ЗАТРАТ (из PMCO по ACPOS):
- MTR - МТР Заказчика (001, 008, 009, 010, 012, 014, 016, 017, 024, 22)
- PODRM - МТР Подрядчика (035, 21)
- PODRR - Работы подрядчика (030, 031, 032, 033, 034, 20)
- PODRU - Услуги подрядчика (003, 004, 005, 006, 007, 011, 013, 018, 019, 020, 021, 022, 023, 036, 037, 038, 23)
- OTHER - Прочее (002, 0024, 015, 025, 026, TZR)

ТИПЫ ЗАТРАТ (WRTTP):
- 01 = Плановые
- 04 = Фактические

РАСЧЕТЫ:
- Отклонение абсолютное = FACT - PLAN
- Отклонение относительное = (FACT/PLAN - 1) * 100%

КЛЮЧЕВЫЕ АТРИБУТЫ ЗАКАЗА

AUFNR  - Номер заказа
KTEXT  - Краткий текст (AUFK-KTEXT)
INGRP  - Группа плановиков (AFIH-INGRP)
AUART  - Вид заказа (AUFK-AUART)
ILART  - Вид работ (AFIH-ILART)
ABCKZ  - Критичность (ILOA-ABCKZ по AFIH-ILOAN)
GSTRP  - Плановое начало (AFKO-GSTRP)
GLTRP  - Плановое окончание (AFKO-GLTRP)
GSTRI  - Фактическое начало (AFKO-GSTRI или QMIH-AUSVN)
GETRI  - Фактическое окончание (AFKO-GETRI или QMIH-AUSBS)
TPLMA  - Установка (узел, маска XXNN.XXX)
TPLNR  - Техническое место (ILOA-TPLNR по AFIH-ILOAN)
EQUNR  - Единица оборудования (AFIH-EQUNR)
CLASS  - Класс ЕО (KLAH-CLASS по KSSK-CLINT)
EQART  - Вид объекта (EQUI-EQART)
PLAN   - Плановые затраты (PMCO, WRTTP=01)
FACT   - Фактические затраты (PMCO, WRTTP=04)
PLANT  - Плановые трудозатраты (AFVV-ARBEI)
FACTT  - Фактические трудозатраты (AFVV-ISMNV)
DABS   - Отклонение (PLAN - FACT)
FLAG   - Превышение (P=план>факт, F=факт>план)
STAT   - Системный статус
USTAT  - Пользовательский статус
PODR   - Подрядчик (AFVC-LIFNR)
DOCN   - Номер договора (AUFK-ZZ_DOGNUM)
QMNUM  - Номер сообщения ТОРО (AFIH-QMNUM)
USER   - Плановик (AUFK-ERNAM)
MAUFNR - Вышестоящий заказ (AFKO-MAUFNR)
DEFNUM - Дефектная ведомость (AUFK-ZZ_DEFNUM)
