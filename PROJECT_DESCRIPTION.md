## 1. ОБЩЕЕ ОПИСАНИЕ

ТИТАН Аудит ТОРО — промышленная BI-система для анализа заказов на техническое обслуживание и ремонт (ТОРО) на предприятиях нефтегазовой отрасли. Загружает данные из SAP, рассчитывает 6 методов риск-скоринга, визуализирует финансовые отклонения, качество данных, оборудование, плановиков и выдаёт приоритеты для аудиторской проверки.

### Ключевые возможности:
- Загрузка и парсинг файлов SAP (.xlsx, .csv) — 23 маппируемых поля
- 6 методов риск-скоринга с непрерывной шкалой 0-10
- 9 аналитических вкладок с интерактивными графиками (Recharts)
- AI-чат аналитик (DeepSeek API / Ollama Qwen3) с автоматическим контекстом
- Иерархическая фильтрация (6 уровней: БЕ → ЗАВОД → ЦЕХ → УСТАНОВКА → ЕО)
- Экспорт в Excel с учётом всех фильтров
- Полностью офлайн-готовая сборка (встроенные шрифты, без внешних CDN)

## 5. 9 АНАЛИТИЧЕСКИХ ВКЛАДОК

### 5.1 Финансы (Finance.jsx → routes_finance.py)
- **Помесячный анализ** — линейный график план/факт с количеством заказов
- **Отклонения по цехам** — heatmap-таблица с RGB-градиентом + **accordion** — клик по строке раскрывает список заказов (20 на стр., пагинация)
- **Отклонения по ТМ** — TOP-15 перерасход + TOP-15 экономия + **accordion** с заказами (20/стр.)
- **ABC-распределение** — donut-диаграмма с легендой (кол-во, сумма, %)
- **Парето 80/20** — какой % заказов = 80% затрат + список заказов в пороге

### 5.2 Сроки (Timeline.jsx → routes_timeline.py)
- **Заказы по месяцам** — столбчатый график количества
- **Средние длительности** — план vs факт по месяцам
- **Средние стоимости** — план vs факт по месяцам
- **KPI**: всего с датами, средняя длительность, средняя стоимость

### 5.3 Виды работ (WorkTypes.jsx → routes_work_types.py)
- **Donut** — плановые vs внеплановые (8 видов работ)
- **Bar chart** — стоимость по видам
- **Помесячный тренд** — TOP-8 видов работ по месяцам
- **KPI**: кол-во видов, внеплановые %, общее отклонение

### 5.4 Плановики (Planners.jsx → routes_planners.py)
- **Группы плановиков (INGRP)** — heatmap-таблица + **accordion** — клик по группе раскрывает список заказов (20/стр., пагинация)
- **TOP-20 пользователей** — по отклонению бюджета
- **Качество данных по пользователям** — heatmap пустых полей (Plan_N, Начало, Конец, ТМ, ЕО, ABC, Вид, ДОГОВОР)
- **Heatmap методов** — какие методы риска срабатывают у каких плановиков

### 5.5 Рабочие места (Workplaces.jsx → routes_workplaces.py)
- **Сводная аналитика** — donut + bar chart по затратам
- **РМ с перерасходом** — heatmap-таблица (TOP-15) + **accordion** с заказами (20/стр., пагинация)
- **РМ с экономией** — heatmap-таблица (TOP-15) + **accordion** с заказами (20/стр., пагинация)
- **KPI**: кол-во РМ, всего заказов, перерасход

### 5.6 Приоритеты аудита (Risks.jsx → routes_risks.py) — КЛЮЧЕВАЯ ВКЛАДКА
- **Radar chart** — % заказов по каждому из 6 методов
- **6 карточек методов** — donut SVG + кол-во, сумма, средний балл, порог
- **Категории заказов**: Красный (>7), Жёлтый (4-7), Серый (1-4), Зелёный (<1)
- **TOP приоритетных заказов** — пагинированная таблица с прогресс-барами
- **Ползунки порогов** — изменение порогов в реальном времени

### 5.7 Качество данных (Quality.jsx → routes_quality.py)
- **Heatmap заполненности** — 23 поля SAP с % заполнения
- **Проблемные поля** — >30% пустых
- **KPI**: общая заполненность %, кол-во проблемных полей

### 5.8 Оборудование (Equipment.jsx → routes_equipment.py)
- **ABC-критичность ЕО** — donut-диаграмма
- **10 классов оборудования** — таблица + bar chart (Насос, Компрессор, Ёмкость, Теплообменник, Колонна, Реактор, Арматура, Трубопровод, Электродвигатель, КИП)
- **Метрики на единицу ЕО** — средние заказы/план/факт по классу
- **TOP-50 ЕО по затратам** — таблица с сортировкой + **раскрывающийся список** (accordion) — по клику на наименование показывает все заказы ЕО с текстом работ, видом, датой, суммой
- **Лидеры по внеплановым** — ABC: A и B с наибольшим кол-вом внеплановых работ
- **Heatmap затрат** — TOP-100 ЕО × месяцы, цветовая интенсивность
- **Частота обслуживания** — таблица до 100 ЕО (30 видимых + прокрутка): Код ЕО, Название, Кол-во заказов, Сумма факт ₽, Средний/Мин/Макс интервал (дни). Сортировка по всем столбцам, accordion с заказами по клику на название

### 5.9 Реестр заказов (Orders.jsx → routes_orders.py)
- **Пагинированная таблица** — 50 заказов на страницу, серверная пагинация
- **Сортировка** — по любой колонке (Risk_Sum по умолчанию)
- **Быстрые фильтры**: Автор, ТМ, Метод, Цех, Завод, РМ, ЕО
- **Расширенный поиск ЕО** — единое поле поиска по названию и коду оборудования (contains, case-insensitive), результаты с кнопкой `+` для добавления тега, теги с `×` для удаления, OR-логика фильтрации
- **Поиск по номерам заказов** — ввод через запятую, теги
- **Экспорт в Excel** — с учётом всех применённых фильтров

## 6. РИСК-СКОРИНГ v2 (6 методов)

### 6.1 Методы

| Метод | Описание | Формула | Вес | Порог по умолч. |
|-------|----------|---------|-----|-----------------|
| **C1-M1** | Перерасход бюджета | (Факт/План - 1) × 100% > порог | 2 | 20% |
| **C1-M6** | Аномалия по истории ТМ | Факт > Медиана(ТМ) × порог% | 2 | 140% |
| **C1-M9** | Незавершённые работы | Статус ∈ {ОТКР, В работе, Внутр.планирование} | 1 | — |
| **C2-M2** | Проблемное оборудование | Кол-во заказов ЕО > порог | 2 | 5 заказов |
| **NEW-9** | Формальное закрытие (декабрь) | Факт_Конец=декабрь И ускоренное выполнение | 2 | 50% |
| **NEW-10** | Возвраты статусов | N_STATUS_RETURNS > порог | 1 | 3 возврата |

### 6.2 Формула Priority_Score

```
Priority_Score = Methods_Total × Multiplier + DQ_Risk × 0.8

Methods_Total  = Σ(Score_Method[i] × Weight[i])
Multiplier     = {0:0, 1:1.0, 2:1.3, 3:1.7, 4:2.2, 5:2.5, 6:3.0}
DQ_Risk        = балл некачественности данных (0-10)
```

### 6.3 Категории заказов

| Категория | Priority_Score | Описание |
|-----------|---------------|----------|
| Красный | > 7 | Явные нарушения (высокий Method_Score, данные хорошие) |
| Жёлтый | 4 — 7 | Подозрительные (средний Method_Score + плохие данные) |
| Серый | 1 — 4 | Непроверяемые (низкий Method_Score, высокий DQ_Risk) |
| Зелёный | < 1 | Чистые |

## 7. AI-ЧАТ АНАЛИТИК

### 7.1 Архитектура
- **Автоматический контекст** — при каждом сообщении собираются данные из ВСЕХ вкладок:
  1. KPI-сводка
  2. 6 методов риска + скоринг
  3. Финансы + ABC + TOP-5 отклонений
  4. Виды работ
  5. Группы плановиков
  6. Рабочие места
  7. Оборудование + классификация
  8. TOP-10 приоритетных заказов
  9. Пробелы качества данных
  10. Активные фильтры

### 7.2 Провайдеры LLM (по приоритету)
1. **DeepSeek API** — через переменную окружения `DEEPSEEK_API_KEY`
2. **Ollama (Qwen3 4B)** — локально на `localhost:11434`
3. **Fallback** — сообщение о недоступности

### 7.3 Возможности
- Память контекста: последние 20 сообщений
- Системный промпт: аналитик ТОРО с полным описанием методологии
- Ответы на русском языке
- Анализ данных в реальном времени с учётом фильтров
